# D6.1 — AFFI Alert Logic Specification

**Watershed:** Upper Sonoita Creek (HUC-12 150503010204), Patagonia, AZ
**Version:** 2026-08-10 — first standalone version of this spec. Previously
the alert logic existed only as code (`src/forecast/alert_engine.py`,
`src/probabilistic/today_feature_status.py`) plus scattered whitepaper
prose; this document consolidates it into one authoritative reference,
closing whitepaper deliverable D6.1.

This document describes every rule AFFI uses to turn a forecast into an
alert level, and every threshold behind those rules, with its source. It
does not describe *why* the underlying discharge/depth numbers are what
they are (see the whitepaper, Sections 4.2–4.7, for the six-stage
pipeline) — it describes only the decision logic layered on top.

---

## 1. Two independent alert systems

AFFI actually runs **two separate classification systems** that serve
different purposes. Conflating them is a common source of confusion, so
they're kept explicitly separate here:

| | Forecast-day alert (Advisory/Watch/Warning) | Live gauge/feature status (Normal/Warning/Danger/Extreme, severity tiers) |
|---|---|---|
| **Input** | 24hr/1hr rainfall percentiles (P10/P50/P90) from the ensemble | Today's live discharge/depth, per gauge or per map feature |
| **Computed by** | `src/forecast/alert_engine.py` (`AlertEngine.classify_day` / `classify_all_days`) | `src/probabilistic/today_feature_status.py` (`severity_tier`) and the Decision Cockpit's gauge badge |
| **Purpose** | 1–7 day forward-looking watch/warning, matches NWS Advisory/Watch/Warning vocabulary | "What does it look like right now, here" — road-by-road, building-by-building |
| **Where shown** | `AlertBanner`, the top-level `current_alert` field | `FloodMap` feature popups, the Decision Cockpit gauge badge |

## 2. Forecast-day alert levels — Advisory / Watch / Warning

### 2.1 Threshold construction

Every threshold is a **fraction of the 10-year, 24-hour NOAA Atlas 14
design storm** (2.97 in for Patagonia, AZ), not a fixed inch value. This
is deliberate: fractions transfer to a new watershed automatically (a
wetter or drier county's 10-year benchmark scales the thresholds with
it), whereas a hardcoded inch value would not.

Source: `config/watersheds/upper_sonoita.yaml`, `alert_thresholds:` block.

| Level | Fraction of 10yr 24hr | Resulting 24hr threshold | Fraction of 10yr 1hr | Resulting 1hr threshold | Ensemble trigger |
|---|---|---|---|---|---|
| **Advisory** | 0.25 | 0.75 in | 0.18 | 0.25 in | ≥20% of ensemble members exceed |
| **Watch** | 0.40 | 1.24 in | 0.36 | 0.50 in | ≥30% of ensemble members exceed |
| **Warning** | 0.65 | 2.02 in | 0.71 | 0.99 in | ≥30% of ensemble members exceed |

The fraction values themselves (0.25/0.40/0.65, etc.) are calibrated for
semi-arid flashy Southwest watersheds, referencing NWS WFO Tucson
operational guidance conventions — not derived from this project's own
data, and stated as such in the config file's own comments.

### 2.2 Decision rule

For a given forecast day, compute the **probability of exceedance
(PoE)** at each level: the percentage of ensemble members whose 24hr (or
1hr) rainfall exceeds that level's threshold (`AlertEngine.
probability_of_exceedance`, plain `mean(values >= threshold) * 100`).

The day's alert level is the **highest level whose trigger condition is
met**, checked in this order (most severe first, first match wins):

```
if PoE(warning, 24hr) >= 30%  or  PoE(warning, 1hr) >= 30%:   WARNING
elif PoE(watch, 24hr)  >= 30%  or  PoE(watch, 1hr)  >= 30%:   WATCH
elif PoE(advisory, 24hr) >= 20%:                              ADVISORY
else:                                                          GREEN
```

Note the asymmetry: WARNING and WATCH can each be triggered by *either*
the 24hr *or* the 1hr threshold (an intense short burst counts even if
the daily total doesn't clear the 24hr bar), but ADVISORY only checks
24hr — a deliberate choice to keep the lowest tier from firing on brief,
non-threatening 1hr blips.

**Unit invariant — read this if you're re-deriving this logic.** Every
value compared against a threshold here must already be in **inches**.
The raw Open-Meteo ensemble arrives in millimeters
(`EnsembleForecastClient.fetch()`); `map_calculator.
compute_daily_statistics()` and `alert_engine.classify_all_days()` both
convert mm→inches internally (`MM_TO_IN = 25.4`) before this comparison
runs. A missing conversion at either of those two call sites is exactly
the bug found and fixed 2026-08-10 (see the whitepaper Changelog) — it
silently produced a permanent false WARNING for about a week. Both
conversions now have regression tests (`tests/test_task1/
test_map_calculator.py`, `tests/test_task1/test_alert_engine.py`).

### 2.3 `current_alert` (the headline number)

`current_alert` in the alert packet is the **maximum alert level across
all 7 forecast days**, not just today's — so a WARNING three days out
still shows as the headline alert today, giving lead time rather than
waiting for the day itself.

## 3. Live gauge/feature status — Normal / Warning / Danger / Extreme

Modeled on Google Flood Hub's convention. Applies to today's live
discharge at the pilot gauge (USGS 09481500) and is shown as a badge in
the Decision Cockpit (`gaugeStatus()` in `DecisionCockpit.tsx`).

| Status | Condition (today's discharge vs. library return-period thresholds) |
|---|---|
| **Normal** | below the 2-year discharge (83.6 cms) |
| **Warning** | between the 2-year and 5-year discharge (83.6–166.2 cms) |
| **Danger** | between the 5-year and 25-year discharge (166.2–317.2 cms) |
| **Extreme** | above the 25-year discharge (>317.2 cms) |

The 25-year threshold stands in for Google Flood Hub's own "~20-year"
Extreme boundary, since this project's library has no stored 20-year
map — the nearest available is 25-year. This substitution is stated
explicitly in code comments (`DecisionCockpit.tsx`) and in the whitepaper.

## 4. Per-feature severity tiers — none / minor / moderate / severe

Applies to individual roads, buildings, and infrastructure on the map
(`src/probabilistic/today_feature_status.py::severity_tier()`), replacing
an earlier binary flooded/not-flooded tag. Bands match the NWS "Turn
Around Don't Drown" public-safety depth guidance:

| Tier | Depth at that feature |
|---|---|
| **none** | < 0.05 m |
| **minor** | 0.05 – 0.3 m |
| **moderate** | 0.3 – 0.6 m |
| **severe** | ≥ 0.6 m (the threshold at which a person can be swept off their feet / a vehicle can float) |

Each feature also carries a `poi_pct` — the Pearson-Tukey-weighted
probability (0.185/0.630/0.185 weights on best/likely/worst scenarios,
`src/probabilistic/risk_map.py::probability_of_inundation()`) that the
feature gets *any* water today, shown alongside the severity tier so a
"minor, 90% confidence" reading is visibly different from a "minor, 15%
confidence" one.

## 5. Delivery policy

> **All AFFI alerts are delivered exclusively to authorized government
> personnel** — county emergency managers, public-works directors, EOC
> staff. No alert is broadcast directly to the public. Public
> communications remain a decision for the responsible government
> official reviewing the AFFI output, not an automated action AFFI takes
> itself.

This is a deliberate liability and trust-preservation decision, not a
missing feature — see whitepaper Section 4.8.

## 6. Change control

Any change to a threshold, fraction, or trigger percentage in this
document must also change `config/watersheds/upper_sonoita.yaml` (or the
equivalent per-feature constants in `today_feature_status.py` /
`DecisionCockpit.tsx`) in the same commit, and vice versa — this document
describes the config, it does not independently define behavior. If the
two ever disagree, the config file is authoritative and this document is
stale until updated.
